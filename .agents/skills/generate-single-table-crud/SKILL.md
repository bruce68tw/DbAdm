# 單一資料表 CRUD

以 DbAdm 的 Column 功能為實際參考，依目標專案慣例產生可串接的單表 CRUD。範例中的關聯查詢只供顯示／權限用途，不代表產生多表寫入。

## 執行所需資訊

從使用者需求及可讀取的專案取得：目標專案路徑、輸出子目錄、功能名稱／程式代碼、資料表（含 schema）、CRUD 使用的 key 與產生方式、欄位型態／長度／可空／預設值、可寫與唯讀欄位、查詢／列表／排序欄位、驗證與登入／功能／資料列權限。下拉來源及顯示關聯只在需求使用時確認。

不要求重填已提供或原碼可確定的資訊；只針對會影響正確性的必要缺口提出精準問題。無法核實的 key、驗證 API、權限規則或相依不可自行杜撰。本 Skill 不包含通用需求問卷，也不建立或存取雲端需求文件。

## 先辨識來源與目標

1. 讀取適用的 AGENTS.md，檢查目標專案狀態及相關既有功能。以此 Skill 所在目錄向上三層定位 DbAdm 根目錄，不硬編碼電腦路徑；DbAdm 與目標專案可能不同。若只收到 Skill 的複本，定位使用者提供的 DbAdm；原檔不可讀時索取來源位置。
2. 讀取 [Column 原檔與串接規則](references/column-pattern.md)，再開啟其中必要原檔。這份索引是已核對紀錄，執行時仍以當前原碼為準；遇到改名或方法變更重新追蹤呼叫。
3. 檢查目標的 csproj、命名空間、Base 相依、View imports／元件、前端全域宣告、腳本載入、路由與建置設定。版本從檔案取得，不從範例推測。若目標缺少 Base API，先核實可用實作或釐清相依方案，不生成假裝可編譯的替代 API，也不搬入整個 Base 專案。
4. 將輸出子目錄解析為目標根目錄內的絕對位置，列出預計檔案對應。辨別它是實際功能目錄還是待整合的輸出包；按目標規範保留 Controllers、Services、Views 與 TypeScript 的相對配置。任意子目錄不一定具備 MVC View 探索或 TS 建置能力，須核對載入／編譯對應；若無法從需求判定，詢問此一差異。不要悄悄改成 DbAdm 或其他預設位置。

## 產生與整合

- 基本產物為 `{Prog}Controller.cs`、`{Prog}Read.cs`、`{Prog}Edit.cs`、`Views/{Prog}/Read.cshtml`、`Edit.cshtml`、`{Prog}.ts`，實際根目錄按上述映射。只在目標確實需要時增加 DTO、模型或整合設定，不固定複製 ColumnDto、ColumnSvc 或 EF 實體。
- `Read.cshtml` 是查詢畫面；新增、修改及檢視共用同一個 `Edit.cshtml`，由 CrudE 切換模式、載入資料與控制可編輯狀態。保留 Read 引入 Edit partial 的結構，不拆成 Create、Update、View 三個頁面。
- 先建立欄位對應：資料庫欄位、讀取 alias、查詢 Fid／Col／Op、編輯 Items、View Fid、TS data、key、驗證。依需求取代業務名稱、schema、表名、joins、欄位與權限；不要只全域替換 Column 字串。
- 保留來源的讀寫委派、前端 payload／回應契約與固定 DOM ID。指定不同 key 時同步調整後端 PkeyFid、查詢條件、隱藏欄位、EditOne 初始化及操作按鈕 key。SQL 值使用已核實的參數機制；識別字來自確認過的 schema，不把任意輸入拼進 SQL。
- 後端可寫白名單與 UI 編輯性須一致。將必要輸入、長度、範圍及業務驗證落在目標已核實的伺服器驗證機制；前端提示配合現有元件與 CrudE。ColumnEdit 未展示自訂伺服器驗證 hook，須查 Base 或目標的實例後才能使用，不能把 View 的 MaxLen 當作完整後端驗證。
- 保留需求所需的登入與權限檢查，核對功能按鈕及伺服器 action 一致；資料列權限欄位依目標來源映射，不能沿用 Column 的專案建立者假定。只修改本功能必要檔案；選單／權限／資料庫資料變更須依本次授權範圍處理，未執行者明列整合事項。
- 單表新增必填欄位、預設值及 key 產生須完整可行。Column 編輯畫面有唯讀欄位，須在共用 Edit 畫面內依需求處理新增模式的輸入或預設值，不另建新增頁面。遇到多表交易或一對多需求，說明超出範圍並釐清要保留的單表工作。

## 驗證與交付

核對 SQL alias／查詢 Fid／View Fid／TS 欄位順序、渲染索引、key 與 Items 的一致性；檢查命名空間、路由、View／腳本位置及相依是否可解析。依目標實際建置方式執行相關 C# 與前端檢查；DbAdm 的建置資訊見參考。以可用的開發環境驗證查詢、分頁、排序、新增、更新、檢視、刪除、驗證失敗與權限拒絕，不對未授權的正式資料執行寫入。

回報完整輸出路徑、採用的來源、必要整合、實際執行的檢查及未能驗證的原因。輸出包若尚未納入目標編譯或執行環境，明確標示，不宣稱 CRUD 已可執行。
